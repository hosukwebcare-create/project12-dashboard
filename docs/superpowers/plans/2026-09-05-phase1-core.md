# 1단계 코어 MVP 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계서 1단계(회원 마스터 · 집중관리일지 · 라운딩 · 현황판 + 공통 인증/권한/설정)를 로컬에서 실행·시연 가능한 수직 슬라이스로 구현한다.

**Architecture:** Next.js App Router 단일 앱. 쓰기는 Server Actions, 공개·배치는 Route Handlers. 모든 데이터 접근은 `ctx`(사용자·활성 지점·역할)를 받는 모듈별 `repo.ts`를 통해서만 하고, repo가 `branch_id` 스코핑을 강제한다. 업무 규칙은 `src/lib/rules/*`의 순수 함수로 분리해 단위 테스트한다.

**Tech Stack:** Next.js 15+ (App Router, TypeScript), Tailwind CSS v4, shadcn/ui, Drizzle ORM + postgres.js, PostgreSQL 17(로컬 brew), zod, jose(JWT 세션) + bcryptjs, Vitest.

## Global Constraints

- UI 문구는 전부 한국어.
- 모든 업무 테이블에 `branch_id`. repo 함수는 반드시 `ctx.branchId`로 필터한다. HQ 관리자도 활성 지점 컨텍스트 안에서만 조회한다.
- 조교(assistant) 역할은 회원의 연락처·주소·생년월일·학부모 정보를 조회할 수 없다(별도 select 목록 사용).
- 기록 테이블(checks, counsel_logs, issues)은 삭제하지 않는다. 수정은 `audit_logs`에 before/after를 남긴다.
- 라운딩 등급은 `a | b | p | na`, 점수는 `p`일 때 규칙 점수 스냅샷. 주차는 월요일 시작.
- 시드 데이터에 실제 인물 정보를 넣지 않는다(스크린샷의 이름·연락처 사용 금지).
- 설계서와의 의도적 차이: 인증은 Auth.js 대신 `jose` 서명 쿠키 + `bcryptjs`로 직접 구현한다(의존성·설정 최소화). PWA 오프라인 큐, CSV 이관, 커스텀 필드, 모의고사 UI는 이번 MVP 범위 밖(스키마만 준비).
- 커밋은 사용자가 요청할 때만 한다. 각 태스크 끝의 "Commit" 단계는 `git add`까지만 수행한다.
