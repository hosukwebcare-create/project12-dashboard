# 10. 보안 설계 (운영 강화)

작성 2026-10-13. **1단계 구현 완료(2026-10-13)**, 2단계는 결정 대기. 운영 중인 플랫폼을 무단 접근에서 지키기 위한 설계다. 시스템 설계서 9장(보안·개인정보)의 원칙을 따르고, 거기서 계획만 하고 아직 만들지 않은 것을 채운다.

> 이 저장소는 공개 저장소다. 이 문서에는 방어 방식만 적는다. 비밀번호·토큰·접속 주소는 어디에도 적지 않는다.

## 1. 지켜야 할 것과 공격 경로

| 지킬 것 | 왜 중요한가 |

| 직원 계정, 특히 본사 관리자 | 본사 계정 하나면 모든 지점을 볼 수 있다 |
| 운영 서버와 DB | 코드 저장소(GitHub)를 손에 넣으면 운영 서버에 아무 코드나 올릴 수 있다 |

| 공격 경로 | 지금 막는 것 | 이번에 더하는 것 |
|---|---|---|
| 비밀번호 무작위 대입 | 계정당 5회 실패 잠금, IP당 20회 차단 | IP 판정을 위조할 수 없게 고침 |
| 훔친 세션 쿠키 재사용 | 12시간 만료, 비밀번호 변경 시 끊김 | 서버 세션 기록 — 로그아웃·강제 로그아웃이 실제로 세션을 없앤다 |

| 내려받은 파일·CSV를 통한 공격 | 파일 형식 판정, nosniff | 파일 응답 격리(sandbox), CSV 수식 실행 방지 |
| 알려진 라이브러리 취약점 | — | Next 보안 패치, 운영 번들에서 개발 도구 제외 |
| 공개 저장소로 비밀 유출 | `.env*` 제외, push 보호 훅(저장소·계정) | push 전 비밀정보·실데이터 파일 검사 |

## 2. 1단계 — 이번 작업 (직원 로그인 방법은 그대로)

### 2.1 서버 세션
- 로그인할 때마다 `auth_sessions`에 한 줄을 만든다. 쿠키(JWT)에는 그 세션 번호만 더 들어간다.
- 매 요청에서 세션이 살아 있는지(폐기·만료 아님) 확인한다. 사용자 조회와 같은 쿼리에서 본다.
- 로그아웃하면 그 세션을 폐기한다. 쿠키를 훔쳐 둔 사람도 그 순간부터 못 쓴다.
- 비밀번호 변경·계정 끄기 → 그 사람의 모든 세션 폐기.
- PIN 전환 → 태블릿의 이전 세션 폐기 후 새 세션.
- 배포 직후 기존 로그인은 한 번 모두 풀린다(세션 번호가 없는 옛 쿠키는 받지 않는다).

### 2.2 내 계정 화면 (`/account`, 모든 직원)
- 내 비밀번호 바꾸기(현재 비밀번호 확인). 관리자가 정해 준 첫 비밀번호를 본인이 바꿀 수 있다.
- 지금 로그인된 기기 목록(시각·IP·브라우저)과 "다른 기기 모두 로그아웃".

### 2.3 로그인 방어
- 접속 IP는 Railway 프록시가 덧붙인 값(X-Forwarded-For 맨 오른쪽)으로 판정한다. 맨 앞 값은 요청자가 마음대로 쓸 수 있어 IP 차단을 피해 갈 수 있었다. 프록시 단계 수는 `TRUSTED_PROXY_HOPS`(기본 1).
- 로그인 뒤 이동 주소(`next`)는 같은 사이트 경로만 허용한다(`//`, `/\`, 제어 문자 거부).
- 비밀번호 해시 강도 bcrypt 10 → 12. 기존 해시는 다음 로그인 때 자동으로 다시 만든다.

### 2.4 보안 기록 (`security_events`, 본사만 열람)
- 로그인 성공·실패·잠김, IP 차단, PIN 실패·잠김, 로그아웃, 강제 로그아웃, 비밀번호 변경을 남긴다.
- 시각·종류·아이디(입력값)·사용자·IP·브라우저만 남긴다. 비밀번호는 어떤 형태로도 남기지 않는다.
- 설정 › 보안 기록(본사)에서 최근 기록과 실패가 몰린 IP·아이디를 본다. 직원 목록에서 "모든 기기 로그아웃".
- 1년 지난 기록은 보관 배치가 지운다.

### 2.5 공개 주소 보호
- `/board/*`, `/api/board/*`, `/api/integrations/*` 에 IP당 분당 요청 수 제한(메모리, 인스턴스별).
- 잔디 주소: 없는 지점과 틀린 토큰에 같은 401로 답한다(지점 코드 찔러 보기 방지).

### 2.6 응답·헤더
- 업로드 파일 응답에 `Content-Security-Policy: sandbox` — 파일 안에 스크립트가 있어도 실행되지 않는다.
- CSV 내려받기: `=`, `+`, `-`, `@`, 탭으로 시작하는 칸 앞에 `'` — 엑셀에서 수식으로 실행되지 않는다.
- `X-Powered-By` 제거, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`.
- `/api/health`: DB 오류 원문을 내보내지 않는다. `rls` 항목으로 DB 계정이 행 보안을 우회하지 않는지 알려 준다(우회하면 서버 로그에 경고).

### 2.7 의존성
- Next 16.3.4 → 16.3.8(보안 패치).
- shadcn(화면 부품 생성 도구)을 개발 의존성으로 옮겨, 운영 의존성 감사에서 관련 없는 경고를 걷어 낸다.
- 목표: `pnpm audit --prod` 에 high·critical 0건.

### 2.8 권한 정밀 점검
- 모든 서버 액션·API에 대해 역할 검사, 다른 지점 데이터 접근(IDOR), 권한 상승, 대량 할당을 점검하고 찾은 것을 고친다.
- `scripts/authz-audit.mjs`(정적 점검)는 그대로 통과해야 한다.
- 점검에서 고친 것:
  - **계정은 사람 하나에 붙어 있다.** 다른 지점에서 지점장인 사람이 우리 지점에선 멘토면, 우리 지점장이 그 비밀번호·PIN 을 바꿔 그 지점 권한을 가질 수 있었다 → 지점장은 어느 지점에서든 멘토·조교인 계정만, 다른 지점에도 속한 계정은 이 지점 역할만 바꾼다. 나머지는 본사.
  - **PIN 세션은 그 지점에만 묶고**, PIN 실패 잠금을 비밀번호 잠금과 분리한다.
  - **근무시간 부풀리기**: 같은 타임 중복 전송, 자기 근무 형태가 아닌 타임 체크, 지난 날짜 출근으로 며칠을 근무로 만들기, 퇴근 후 한참 뒤 다시 출근으로 빈 시간 채우기 → 중복 제거, 형태 검사, 출근은 오늘만, 퇴근 취소는 30분 안, 초과근무 하루 12시간 상한. 지점장 본인·다른 지점장의 시급은 본사만.
  - **다른 지점 id 끼워 넣기**: 상담 일정·이슈 담당자, 일정의 회원, 결제의 회원·등록 기간, 좌석 요금 등급을 이 지점 것인지 확인한다. 상담 일정 담당자 목록이 전 지점 직원을 보여 주던 것을 이 지점 직원으로 줄인다.
  - 처음 설정 화면의 동시 요청을 자문 잠금으로 줄 세운다.

### 2.9 공개 저장소 보호
- push 전 훅이 보내는 커밋에서 비밀정보 모양(접속 문자열·토큰·개인키)과 실데이터 파일(`.xlsx`, `.csv`, `.env`, 대사 결과)을 찾으면 push 를 막는다.

## 3. 2단계 — 사용자 결정 후

- **본사·지점장 2단계 인증(TOTP)**: 휴대폰 인증 앱(Google Authenticator 등)의 6자리 숫자를 비밀번호 다음에 입력. 시스템 설계서 9장의 "본사 계정 TOTP 옵션". 본인이 내 계정 화면에서 켜고, 본사가 분실 시 초기화한다.
- 태블릿 PIN 을 등록 기기에서만 허용.

## 4. 사람이 해야 하는 일 (코드 밖)

| 항목 | 이유 |
|---|---|
| GitHub hosukwebcare-create 계정 2단계 인증 | 이 계정이 털리면 운영 서버에 아무 코드나 배포된다 |
| Railway 계정 2단계 인증 | 환경변수(DB 비밀번호·세션 키)와 DB 가 여기 있다 |
| GitHub 저장소 Secret scanning·Push protection·Dependabot alerts 켜기 | 공개 저장소는 무료. 실수로 올린 비밀을 막고 취약 라이브러리를 알린다 |
| GitHub main 브랜치 보호(강제 push·삭제 금지) | 기록을 지우고 덮어쓰는 공격을 막는다 |
| 운영 `DATABASE_URL` 이 superuser 가 아닌 `byeolha_app` 계정인지 | superuser 는 행 보안을 무시한다. `/api/health` 의 `rls` 로 확인 |
| `SESSION_SECRET` 32자 이상 무작위, 유출 의심 시 교체 | 교체하면 모든 로그인이 풀린다 |

## 5. 검증

- 단위: IP 판정, `next` 검사, CSV 이스케이프, 요청 수 제한.
- 통합: 로그아웃한 세션 거부, 비밀번호 변경·계정 끄기 시 세션 폐기, 다른 기기 로그아웃, 보안 기록 저장, 권한 수정분.
- E2E: 로그인·로그아웃·PIN 전환 기존 시나리오 + 로그아웃 뒤 옛 쿠키 거부 + 내 계정 비밀번호 변경.
- 정적 권한 점검, 의존성 감사, 운영 배포 후 헤더·health 확인.
