# 운영 가이드

## 환경 변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 예 | PostgreSQL 연결 문자열 |
| `SESSION_SECRET` | 예 | 세션 JWT 서명 키, 32자 이상 무작위 |
| `JOB_SECRET` | 배치 사용 시 | `/api/jobs/*` 호출 시 `x-job-secret` 헤더 값 |
| `STORAGE_DRIVER` | 선택 | `local`(기본) 또는 `gcs` |
| `STORAGE_DIR` | local일 때 | 회원 파일 저장 디렉터리 (기본 `./storage`) |
| `GCS_BUCKET`, `GCS_PREFIX` | gcs일 때 | 버킷 이름과 객체 접두어. 인증은 Cloud Run 서비스 계정(ADC)으로 자동 처리되며 로컬에서는 `GOOGLE_APPLICATION_CREDENTIALS` 사용 |
| `ALIMTALK_PROVIDER` | 선택 | `mock`(기본, 실제 발송 없음) · `nhn`(NHN Cloud) · `solapi`(솔라피) · `http`(범용) |
| `ALIMTALK_NHN_APP_KEY`, `ALIMTALK_NHN_SECRET_KEY`, `ALIMTALK_SENDER_KEY` | `nhn`일 때 | NHN Cloud Notification 앱키·시크릿·발신프로필 키 |
| `ALIMTALK_SOLAPI_API_KEY`, `ALIMTALK_SOLAPI_API_SECRET`, `ALIMTALK_SOLAPI_PF_ID`, `ALIMTALK_SOLAPI_FROM` | `solapi`일 때 | 솔라피 API 키·시크릿·카카오 채널 pfId·발신번호 |
| `ALIMTALK_ENDPOINT`, `ALIMTALK_API_KEY` | `http`일 때 | 그 밖의 딜러용 범용 JSON POST. 요청 형식은 `HttpProvider`에서 조정 |
| `RETENTION_DAYS` | 선택 | 퇴원 후 개인정보 보관 일수(기본 365). 배치 `/api/jobs/retention`이 지난 회원을 익명화 |
| `WEBHOOK_ALLOW_PRIVATE` | 아니오 | 메신저 웹훅이 사설망 주소를 가리키는 것을 허용 (`true`). 로컬·메타데이터 주소는 항상 차단 |
| `HERO_WEBHOOK_SECRET` | HERO 연동 시 | HERO 웹앱이 보내는 `x-hero-signature`(HMAC-SHA256 hex) 검증 키 |

## 배포 (GCP 기준)

실사용 전환까지의 순서(호스팅 선택, 부트스트랩, 시트 적재, 기기 준비, 전환 주간)는 `docs/07_배포_체크리스트.md`에 있다. 운영 DB의 첫 계정은 `scripts/bootstrap.ts`로 만든다.

1. Cloud SQL(PostgreSQL 16) 생성, `DATABASE_URL` 발급.
2. `pnpm build` → 컨테이너 이미지 → Cloud Run(asia-northeast3, min 1 인스턴스). 환경 변수는 Secret Manager로 주입.
3. 최초 1회 `pnpm db:migrate` (Cloud Run Job 또는 로컬에서 Cloud SQL Proxy 경유).
4. Cloud Scheduler
   - 매 5분 `POST /api/jobs/alimtalk` (헤더 `x-job-secret`)
   - 매 1분 `POST /api/jobs/outbox`
   - 매일 03:00 `POST /api/jobs/retention`

빌드·배포 자동화는 `deploy/cloudbuild.yaml`(Cloud Build → Artifact Registry → 마이그레이션 Job → Cloud Run)로 한다. 이미지는 루트 `Dockerfile`(standalone 출력)이며 `runner`·`migrate` 두 타깃이 있다.
5. 파일 저장소: `STORAGE_DRIVER=gcs`, `GCS_BUCKET` 지정. 버킷은 비공개, 서비스 계정에 `roles/storage.objectAdmin`. Cloud Run 디스크는 휘발성이라 local 드라이버는 운영에 쓰지 않는다.
6. 백업: Cloud SQL 자동 백업 + PITR, GCS 버킷 버전 관리 켜기.

로컬 서버 대안: `deploy/docker-compose.yml`(postgres + migrate + app + caddy HTTPS + 배치 cron). `deploy/.env.production.example`을 복사해 값을 채우고 `docker compose -f deploy/docker-compose.yml --env-file deploy/.env.production up -d --build`. 백업은 `scripts/backup.sh`(pg_dump, 선택적으로 GCS 업로드, 90일 보관)를 cron에 건다.

## 외부 연동

### 카카오 알림톡
- 발주사가 딜러사(NHN Cloud, 솔라피 등)에서 발신프로필·템플릿 승인을 받는다.
- 본사 관리자가 설정 › 알림톡 템플릿에 **승인된 코드와 본문**을 등록한다. 변수는 `#{이름}` 형식. 이름·지점·좌석은 자동 채움.
- `ALIMTALK_PROVIDER=http`로 바꾸고 엔드포인트·키를 넣는다. 딜러 API 요청 필드가 다르면 `HttpProvider.send()`만 수정한다.
- 발송은 큐에 쌓인 뒤 즉시 처리되며 실패 건은 이력 화면에서 재발송한다.

### HERO 학습진단
HERO 웹앱이 설문 완료 시 아래를 호출한다.

```
POST /api/integrations/hero
x-hero-signature: <HMAC-SHA256(body, HERO_WEBHOOK_SECRET) hex>
{
  "branchCode": "DT2",
  "memberPhone": "010-0000-0101",      // 또는 memberName + seatNo
  "externalId": "hero-response-123",
  "summary": { "type": "탐구형", "score": 82 },
  "resultUrl": "https://project12-hero.replit.app/result/123",
  "takenAt": "2026-09-01T10:00:00+09:00"
}
```
응답 201(신규)/200(갱신)/422(회원 미일치)/404(지점 코드)/401(서명). 결과는 회원 상세 › 파일·진단 탭에 표시된다.

### 사내 메신저 (Rocket.Chat / Mattermost / Slack)

웹훅 URL은 저장할 때와 보낼 때 모두 검사한다. 로컬(127.0.0.1, localhost), 링크로컬·클라우드 메타데이터(169.254.0.0/16, metadata.google.internal), 특수 대역은 항상 거부한다. 메신저를 사설망(10/8, 172.16/12, 192.168/16)에 두는 온프레미스 구성이면 `WEBHOOK_ALLOW_PRIVATE=true`를 준다.
- 메신저에서 인커밍 웹훅 URL을 만든다.
- 지점 설정 › 메신저 연동에 URL과 구독 이벤트(이슈 보고, 고벌점, 회차 완료)를 등록한다.
- 이벤트는 `event_outbox`에 쌓이고 배치가 `{ "text": "..." }` JSON으로 게시한다. 실패 건은 설정 화면에서 재전송.

## 지점 격리 (RLS)

앱 계층 스코핑에 더해 PostgreSQL 행 수준 보안이 두 번째 방어선이다. 로그인 요청은 지점 컨텍스트가 설정된 트랜잭션 안에서 실행되고, 24개 업무 테이블의 정책이 다른 지점 행을 숨긴다.

- 운영 DB 접속 계정은 **superuser가 아니어야 한다**. superuser는 RLS를 무시한다. 테이블 소유자 계정은 `FORCE ROW LEVEL SECURITY`로 적용된다(마이그레이션 0004).
- Railway·도커 이미지의 기본 계정 `postgres`는 superuser다. `scripts/db-app-role-prod.sql`로 앱 계정(`byeolha_app`)을 만들고 테이블 소유권을 넘긴 뒤 그 계정으로 접속한다. Cloud SQL 기본 사용자는 superuser가 아니지만 같은 스크립트를 써도 된다.
- 로컬 통합 테스트·E2E는 `scripts/db-local-app-role.sql`이 만드는 비superuser 역할 `byeolha_app`으로 접속한다. `pnpm db:reset:test`, `pnpm db:reset:e2e`가 마이그레이션 적용과 권한 부여까지 한다. `drizzle-kit push`는 정책의 USING 식을 반영하지 않으므로 테스트 DB에는 쓰지 않는다.
- 정책이 잘 적용됐는지 확인: `select polname from pg_policy where polqual is null` 결과가 비어 있어야 한다.

## 로그인·PIN 잠금

비밀번호와 조교 PIN 모두 5회 연속 실패하면 대상 계정이 10분간 잠긴다. 잠금은 `users.locked_until`이며, 급하면 지점장이 설정 › 사용자에서 비밀번호나 PIN을 다시 설정하면 풀린다.

## 헬스체크

`GET /api/health` 는 DB 연결까지 확인해 `{ ok: true }` 를 돌려준다. Cloud Run 상태 확인, 업타임 모니터링(5분 간격)에 쓴다. 실패 시 503.

## 배치 엔드포인트

| 경로 | 주기 | 동작 |
|---|---|---|
| `POST /api/jobs/alimtalk` | 5분 | 대기 중 알림톡 발송 |
| `POST /api/jobs/outbox` | 1분 | 메신저 웹훅 이벤트 전송 |
| `POST /api/jobs/retention` | 매일 | 퇴원 후 보관기간 지난 회원 익명화 |

모두 `x-job-secret` 헤더 필요.

## 데이터 보호

- 로그인은 5회 실패 시 10분 잠기며, 없는 아이디와 틀린 비밀번호는 같은 메시지로 답한다.
- 응답에 `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, 운영에서는 HSTS 헤더가 붙는다(`next.config.ts`).
- 퇴원 후 `RETENTION_DAYS`가 지난 회원은 배치가 이름을 `탈퇴회원-xxxx`로 바꾸고 연락처·생년월일·주소·메모·학부모·파일을 지운다. 상담·체크 기록은 통계용으로 남는다.

- 조교 역할은 회원 연락처·주소·생년월일·학부모 정보를 조회할 수 없다.
- 회원 상세·파일 열람은 `access_logs`, 모든 수정은 `audit_logs`에 남는다 (설정 › 감사 로그).
- 현황판은 지점 토큰 URL로만 열리며 이름 마스킹 옵션이 있다. 토큰은 재발급 시 즉시 무효.
