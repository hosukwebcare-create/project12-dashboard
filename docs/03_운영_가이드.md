# 운영 가이드

## 환경 변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 예 | PostgreSQL 연결 문자열 |
| `SESSION_SECRET` | 예 | 세션 JWT 서명 키, 32자 이상 무작위 |
| `JOB_SECRET` | 배치 사용 시 | `/api/jobs/*` 호출 시 `x-job-secret` 헤더 값 |
| `STORAGE_DRIVER` | 선택 | `local`(기본) 또는 `gcs` |
| `STORAGE_DIR` | local일 때 | 회원 파일 저장 디렉터리 (기본 `./storage`) |
| `GCS_BUCKET`, `GCS_PREFIX` | gcs일 때 | 버킷 이름과 객체 접두어. 인증은 Cloud Run 서비스 계정(ADC)으로 자동 처리되며 로컬에서는 `GOOGLE_APPLICATION_CREDENTIALS` 사용 |
| `ALIMTALK_PROVIDER` | 선택 | `mock`(기본, 실제 발송 없음) · `nhn`(NHN Cloud) · `solapi`(솔라피) · `http`(범용) |
| `ALIMTALK_NHN_APP_KEY`, `ALIMTALK_NHN_SECRET_KEY`, `ALIMTALK_SENDER_KEY` | `nhn`일 때 | NHN Cloud Notification 앱키·시크릿·발신프로필 키 |
| `ALIMTALK_SOLAPI_API_KEY`, `ALIMTALK_SOLAPI_API_SECRET`, `ALIMTALK_SOLAPI_PF_ID`, `ALIMTALK_SOLAPI_FROM` | `solapi`일 때 | 솔라피 API 키·시크릿·카카오 채널 pfId·발신번호 |
| `ALIMTALK_ENDPOINT`, `ALIMTALK_API_KEY` | `http`일 때 | 그 밖의 딜러용 범용 JSON POST. 요청 형식은 `HttpProvider`에서 조정 |
| `RETENTION_DAYS` | 선택 | 퇴원 후 개인정보 보관 일수(기본 365). 배치 `/api/jobs/retention`이 지난 회원을 익명화 |
| `WEBHOOK_ALLOW_PRIVATE` | 아니오 | 메신저 웹훅이 사설망 주소를 가리키는 것을 허용 (`true`). 로컬·메타데이터 주소는 항상 차단 |
| `HERO_WEBHOOK_SECRET` | HERO 연동 시 | HERO 웹앱이 보내는 `x-hero-signature`(HMAC-SHA256 hex) 검증 키 |
| `TRUSTED_PROXY_HOPS` | 선택 | 공인 IP 를 덧붙이는 프록시 단계 수(기본 1 = Railway·Cloud Run). 앞에 Cloudflare 같은 것을 두면 2. 로그인 차단·요청 수 제한·보안 기록의 IP 판정에 쓴다 |

## 배포 (GCP 기준)

실사용 전환까지의 순서(호스팅 선택, 부트스트랩, 시트 적재, 기기 준비, 전환 주간)는 `docs/07_배포_체크리스트.md`에 있다. 운영 DB의 첫 계정은 `scripts/bootstrap.ts`로 만든다.

1. Cloud SQL(PostgreSQL 16) 생성, `DATABASE_URL` 발급.
2. `pnpm build` → 컨테이너 이미지 → Cloud Run(asia-northeast3, min 1 인스턴스). 환경 변수는 Secret Manager로 주입.
3. 최초 1회 `pnpm db:migrate` (Cloud Run Job 또는 로컬에서 Cloud SQL Proxy 경유).
4. 배치는 앱이 스스로 돈다(`src/lib/scheduler.ts`). Cloud Scheduler를 따로 걸 필요가 없다. 외부 스케줄러를 쓰려면 `SCHEDULER=off`로 끄고 `/api/jobs/*`를 호출한다.

빌드·배포 자동화는 `deploy/cloudbuild.yaml`(Cloud Build → Artifact Registry → 마이그레이션 Job → Cloud Run)로 한다. 이미지는 루트 `Dockerfile`(standalone 출력)이며 `runner`·`migrate` 두 타깃이 있다.
5. 파일 저장소: `STORAGE_DRIVER=gcs`, `GCS_BUCKET` 지정. 버킷은 비공개, 서비스 계정에 `roles/storage.objectAdmin`. Cloud Run 디스크는 휘발성이라 local 드라이버는 운영에 쓰지 않는다.
6. 백업: Cloud SQL 자동 백업 + PITR, GCS 버킷 버전 관리 켜기.

로컬 서버 대안: `deploy/docker-compose.yml`(postgres + migrate + app + caddy HTTPS + 배치 cron). `deploy/.env.production.example`을 복사해 값을 채우고 `docker compose -f deploy/docker-compose.yml --env-file deploy/.env.production up -d --build`. 백업은 `scripts/backup.sh`(pg_dump, 선택적으로 GCS 업로드, 90일 보관)를 cron에 건다.

## 외부 연동

### 카카오 알림톡
- 발주사가 딜러사(NHN Cloud, 솔라피 등)에서 발신프로필·템플릿 승인을 받는다.
- 본사 관리자가 설정 › 알림톡 템플릿에 **승인된 코드와 본문**을 등록한다. 변수는 `#{이름}` 형식. 이름·지점·좌석은 자동 채움.
- `ALIMTALK_PROVIDER=http`로 바꾸고 엔드포인트·키를 넣는다. 딜러 API 요청 필드가 다르면 `HttpProvider.send()`만 수정한다.
- 발송은 큐에 쌓인 뒤 즉시 처리되며 실패 건은 이력 화면에서 재발송한다.

### HERO 학습진단
HERO 웹앱이 설문 완료 시 아래를 호출한다.

```
POST /api/integrations/hero
x-hero-signature: <HMAC-SHA256(body, HERO_WEBHOOK_SECRET) hex>
{
  "branchCode": "DT2",
  "memberPhone": "010-0000-0101",      // 또는 memberName + seatNo
  "externalId": "hero-response-123",
  "summary": { "type": "탐구형", "score": 82 },
  "resultUrl": "https://project12-hero.replit.app/result/123",
  "takenAt": "2026-09-01T10:00:00+09:00"
}
```
응답 201(신규)/200(갱신)/422(회원 미일치)/404(지점 코드)/401(서명). 결과는 회원 상세 › 파일·진단 탭에 표시된다.

### 사내 메신저 (잔디 / Rocket.Chat / Mattermost / Slack)

웹훅 URL은 저장할 때와 보낼 때 모두 검사한다. 로컬(127.0.0.1, localhost), 링크로컬·클라우드 메타데이터(169.254.0.0/16, metadata.google.internal), 특수 대역은 항상 거부한다. 메신저를 사설망(10/8, 172.16/12, 192.168/16)에 두는 온프레미스 구성이면 `WEBHOOK_ALLOW_PRIVATE=true`를 준다.
- 메신저에서 인커밍 웹훅 URL을 만든다.
- 지점 설정 › 메신저 연동에 URL과 구독 이벤트(이슈 보고, 고벌점, 회차 완료, 해 주세요 올라옴, 인수인계 공지)를 등록한다.
- 이벤트는 `event_outbox`에 쌓이고 배치가 게시한다. 형식은 주소로 정한다(`src/lib/rules/webhook.ts`): `wh.jandi.com`이면 잔디 커넥트 형식(`{ body, connectColor, connectInfo }` + `Accept: application/vnd.tosslab.jandi-v2+json`, 본문 5,000자), 그 밖에는 `{ "text": "..." }` JSON. 실패 건은 설정 화면에서 재전송.

**잔디 → 플랫폼('해 주세요')**: 잔디 커넥트의 아웃고잉 웹훅이 키워드(예: `해주세요`)로 시작하는 글을 `POST /api/integrations/jandi/{지점코드}`로 보낸다. 지점장이 설정 › 지점·현황판에 잔디가 만든 토큰을 저장해 두면(해시 보관) 토큰이 맞는 글만 받아 인수인계 '해 주세요'에 올리고 지점 사람들에게 알린다. 응답은 잔디 형식이라 대화방에 "올렸습니다" 답이 남는다. 토큰이 틀리면 401, 지점 코드가 없으면 404, 내용이 비면 200 으로 안내 문구를 돌려준다(잔디는 200 만 보여 준다).

## 지점 격리 (RLS)

앱 계층 스코핑에 더해 PostgreSQL 행 수준 보안이 두 번째 방어선이다. 로그인 요청은 지점 컨텍스트가 설정된 트랜잭션 안에서 실행되고, 24개 업무 테이블의 정책이 다른 지점 행을 숨긴다.

- 운영 DB 접속 계정은 **superuser가 아니어야 한다**. superuser는 RLS를 무시한다. 테이블 소유자 계정은 `FORCE ROW LEVEL SECURITY`로 적용된다(마이그레이션 0004).
- Railway·도커 이미지의 기본 계정 `postgres`는 superuser다. `scripts/db-app-role-prod.sql`로 앱 계정(`byeolha_app`)을 만들고 테이블 소유권을 넘긴 뒤 그 계정으로 접속한다. Cloud SQL 기본 사용자는 superuser가 아니지만 같은 스크립트를 써도 된다.
- 로컬 통합 테스트·E2E는 `scripts/db-local-app-role.sql`이 만드는 비superuser 역할 `byeolha_app`으로 접속한다. `pnpm db:reset:test`, `pnpm db:reset:e2e`가 마이그레이션 적용과 권한 부여까지 한다. `drizzle-kit push`는 정책의 USING 식을 반영하지 않으므로 테스트 DB에는 쓰지 않는다.
- 정책이 잘 적용됐는지 확인: `select polname from pg_policy where polqual is null` 결과가 비어 있어야 한다.

## 로그인·PIN 잠금

비밀번호와 조교 PIN 모두 5회 연속 실패하면 대상 계정이 10분간 잠긴다. 둘은 따로 센다 — 비밀번호는 `users.locked_until`, PIN 은 `users.pin_locked_until`. 같이 세면 태블릿에서 PIN 을 몇 번 틀리는 것만으로 그 사람의 비밀번호 로그인까지 막히기 때문이다. 본사의 **잠금 해제**는 둘 다 푼다. 급하면 지점장이 비밀번호를 다시 정해도 비밀번호 잠금이 풀린다.

## 헬스체크

`GET /api/health` 는 DB 연결까지 확인해 `{ ok: true }` 를 돌려준다. Cloud Run 상태 확인, 업타임 모니터링(5분 간격)에 쓴다. 실패 시 503(오류 원문은 서버 로그에만 남는다).

- `rls`: 앱이 접속한 DB 계정이 지점 격리를 지키는가. **`false` 면 superuser·BYPASSRLS 계정으로 접속 중이라 지점 격리가 꺼진 것과 같다** — 위 "지점 격리" 절대로 앱 계정으로 바꾼다. 서버 기동 로그에도 `[security]` 경고가 찍힌다.
- `schema`: 적용된 마이그레이션 수/코드에 있는 수(예 `17/17`). 앞이 작으면 기동 때 자동 마이그레이션이 실패한 것이다 — 서버 로그의 `[migrate]` 를 본다.
- `commit`: 떠 있는 커밋. `timeZone`·`localTime`: 서버 시간대.

## 배치 엔드포인트

앱 프로세스 안의 스케줄러(`src/lib/scheduler.ts`)가 서버 기동과 함께 돈다. 같은 배치가 겹치지 않도록 Postgres 자문 잠금을 잡으므로 인스턴스를 늘려도 한 대만 실행한다.

| 배치 | 기본 주기 | 조절 | HTTP 경로 |
|---|---|---|---|
| 알림톡 발송 | 300초 | `SCHEDULER_ALIMTALK_SEC` | `POST /api/jobs/alimtalk` |
| 메신저 웹훅 전송 | 60초 | `SCHEDULER_OUTBOX_SEC` | `POST /api/jobs/outbox` |
| 보관기간 익명화 | 매일 04시 | `SCHEDULER_RETENTION_AT` | `POST /api/jobs/retention` |

`SCHEDULER=off`로 끄고 외부 스케줄러를 쓸 수 있다(HTTP 경로, `x-job-secret` 헤더 필요). 두 방식이 겹쳐도 같은 자문 잠금을 쓰므로 중복 발송은 나지 않는다.
개발 모드에서는 기본으로 꺼져 있고 `SCHEDULER=on`일 때만 돈다.

서버 시간대는 `TZ=Asia/Seoul`이어야 한다(운영 이미지에 포함). 화면의 '오늘'이 서버 로컬 날짜라서, UTC로 돌면 21시 이후 하루가 어긋난다. `/api/health`의 `timeZone`으로 확인한다.

## 데이터 보호

- 로그인은 5회 실패 시 계정이 10분 잠기며, 없는 아이디와 틀린 비밀번호는 같은 메시지로 답한다. 아이디를 바꿔 가며 찍는 시도는 IP 기준으로도 막는다(10분에 20회, `src/lib/auth/login-throttle.ts`). 본사 관리자는 설정 › 사용자에서 잠금을 즉시 풀 수 있다.
- **세션은 서버에 기록된다**(`auth_sessions`). 쿠키(JWT)에는 세션 번호만 더 실리고, 매 요청에서 그 세션이 폐기·만료되지 않았는지 본다. 그래서 로그아웃·강제 로그아웃·비밀번호 변경·계정 끄기가 그 즉시 효력을 갖는다(쿠키를 복사해 둔 사람도 그때부터 못 쓴다). 세션 번호가 없는 예전 쿠키는 받지 않는다. 직원은 내 계정(`/account`)에서 로그인된 기기를 보고 끊을 수 있다.
- PIN 으로 연 세션은 그 지점에만 묶인다(`auth_sessions.branch_id`). PIN 을 알아낸 사람이 그 조교의 다른 지점 권한까지 쓰지 못하게.
- IP 는 `X-Forwarded-For` 의 **오른쪽**(우리 프록시가 붙인 쪽) 공인 주소로 판정한다(`src/lib/client-ip.ts`). 맨 앞 값은 요청자가 마음대로 적을 수 있어서 그걸 믿으면 IP 차단을 피해 간다.
- 로그인 없이 열린 주소에는 IP 당 요청 수 제한이 있다: 현황판 분당 600, 잔디·HERO 분당 120(`src/lib/rate-limit.ts`, 인스턴스별 메모리). 넘으면 429.
- **보안 기록**(`security_events`, 설정 › 보안 기록, 본사만): 로그인 성공·실패·잠김, IP 차단, PIN 전환·실패, 로그아웃, 강제 로그아웃, 비밀번호 변경. 비밀번호·PIN 은 어떤 형태로도 남기지 않는다. 보관 배치가 1년 지난 기록과 끝난 지 30일 지난 세션 행을 지운다.
- 비밀번호 해시는 bcrypt 12. 예전(10) 해시는 다음 로그인 때 다시 만든다.
- 로그인 뒤 이동 주소(`next`)는 같은 사이트 경로만 허용한다(`//`, `/\` 등 거부, `src/lib/safe-next.ts`).
- 업로드 파일(PNG·JPEG) 응답은 `Content-Security-Policy: sandbox` 로 격리하고, 근무 CSV 는 `=`·`+`·`-`·`@` 로 시작하는 글자 칸 앞에 `'` 를 붙여 엑셀에서 수식으로 실행되지 않게 한다.
- 응답에 CSP(`default-src 'self'`, `frame-ancestors 'none'`, `form-action 'self'` 등), `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`·`Cross-Origin-Resource-Policy: same-origin`, 운영에서는 HSTS 헤더가 붙는다. `X-Powered-By` 는 끈다(`next.config.ts`).
- 의존성: `pnpm audit --prod` 가 high·critical 0건이어야 한다. 하위 패키지 보안 패치는 `pnpm-workspace.yaml` 의 `overrides` 로 올린다.
- 퇴원 후 `RETENTION_DAYS`가 지난 회원은 배치가 이름을 `탈퇴회원-xxxx`로 바꾸고 연락처·생년월일·주소·메모·학부모·파일을 지운다. 상담·체크 기록은 통계용으로 남는다.

- 조교 역할은 회원 연락처·주소·생년월일·학부모 정보를 조회할 수 없다.
- 회원 상세·파일 열람은 `access_logs`, 모든 수정은 `audit_logs`에 남는다 (설정 › 감사 로그). 감사 로그에는 비밀번호·PIN·해시가 `***`로, 연락처가 `010-****-5678`로 저장된다 — 변경 이력이 개인정보를 한 번 더 쌓아 두지 않게 한다(`src/lib/audit.ts`).
- 현황판은 지점 토큰 URL로만 열리며 이름 마스킹 옵션이 있다. 토큰은 재발급 시 즉시 무효.
