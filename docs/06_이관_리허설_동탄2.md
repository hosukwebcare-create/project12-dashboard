### 시트 관행 (파서에 반영함)

- **좌석번호 칸에 상태를 적는다.** 숫자면 등록 회원의 좌석, `상담`이면 상담 중, `종료`면 퇴원. 140명 중 좌석 55, 상담 14, 종료 71.
- **이름 뒤 표기.** `/S`, `/s`는 단기(25명). `/3`(25명), `/2`, `/n`(2명)은 뜻이 확인되지 않아 이름에서 떼어 메모에 "시트 표기 /3"으로 남기고 경고를 낸다. `김지민B`처럼 붙여 쓴 영문자는 동명이인 구분이라 이름의 일부로 둔다. `박민서B/S`, `장은진/,S` 같은 복합 표기도 처리한다.
- **주소 칸에 등록기간을 적는다.** 여름 단기 회원 25명의 주소 칸이 `7월22~8월17일[27일]` 형태다. 주소가 아니라 기간으로 읽어 등록기간에 넣고 주소는 비운다.
- **연락처 오타.** 보호자 연락처 1건이 12자리다. 형식이 맞지 않는 번호는 저장을 막지 않고 메모에 원문을 남긴다.
- **날짜 형식.** 생년월일은 `2007/09/25`가 대부분이고 `2007/9999`, `2007.0925` 같은 2건은 읽지 못해 비운다. 첫 등원일은 `2026-06-29`.
- **계열.** 이과 28, 문과 24, 예체능 9 외에 `일반` 2, `편입` 1은 우리 계열 목록에 없어 비우고 경고한다.
- **헤더.** `Column 7`(학생/성인 구분)은 헤더가 없어 자동 매핑이 안 된다. 이관 화면에서 손으로 "구분"에 매핑해야 한다. `보호자 성함`, `첫 등원일`은 별칭에 추가했다.
- **마케팅 SMS 동의**는 2026-09-10 에 회원 정식 항목(`marketing_opt_in`)으로 넣었다. 동의·거부·**미확인** 세 값을 구분한다. 시트 140행 중 동의 61 · 거부 58 · 빈칸 21 이고, 빈칸을 거부로 바꾸면 실제로 동의한 사람에게 못 보내게 되므로 null 로 둔다.

1. 이름 뒤 `/3`, `/2`, `/n`의 뜻. 등록 개월 수인지, 학년인지에 따라 등록기간이나 학년으로 옮긴다.

3. 계열 `일반`, `편입`을 목록에 추가할지.
4. 마케팅 SMS 동의를 커스텀 필드로 둘지.

## 3. 게시용 회원생활관리 시트 (라운딩·현황판)

- 주차별 탭 44개(2025년 11월 5주 ~ 2026년 8월 6주). 탭 하나가 한 주이고 열은 좌석(55석: 7~77번, 중간 결번 있음), 행은 날짜별로 출석, 플래너, R1~R11, 영단어, 점검완료 15줄이다.
- 셀 값은 `a`, `b`, `A`, `B`, `bb`, `aa`, `ba` 같은 문자와 벌점 숫자(2, 3, 5, 6, 8). 대소문자와 겹쳐 쓴 값이 섞여 있어 규칙이 느슨하다.
- 벌점 규칙은 탭 위쪽에 문장으로 적혀 있고 주마다 바뀌었다(이동금지 5점, 휴대폰 미제출 2점 또는 5점, 무단 미등원 8점, 지각 4점, 졸음 3점). 플랫폼의 벌점 규칙 표와 스냅샷 방식에 맞는다.
- **설정 확인 사항**: 동탄2는 하루 회차가 11회(R1~R11)다. 지점 설정 기본값 12를 11로 바꿔야 한다. 좌석은 77번까지 쓰되 결번이 있으므로 좌석 마스터를 이 시트의 좌석 열로 만든다.
- 과거 주차 이관은 통계 목적 외에는 가치가 낮다. 전환 시점 기준 최근 4주만 스크립트로 옮겨 주간 벌점 합계가 이어지게 하는 것을 권장한다.

## 6. 전체 적재 실행 (2026-09-06)

시트 5개를 해석 없이 그대로 개발 DB의 동탄2 지점에 넣었다. 스크립트는 `scripts/migrate-sheets.ts`이며 재실행하면 지점의 업무 데이터를 지우고 다시 넣는다(계정·설정은 유지).

```bash
pnpm exec tsx scripts/migrate-sheets.ts --branch DT2 --dir ~/Downloads \
  --members "고객정보시트_프로젝트12_동탄2.xlsx" --counsel "(동탄) 집중관리일지 -2026.07.xlsx" \
  --board "게시용 회원생활관리 시트_프로젝트12_동탄2.xlsx" --meals "식사 주문시트_프로젝트12(2026)_동탄2.xlsx" \
  --worklog "조교근무일지(2026)_ 동탄2.xlsx"
```

|---|---|
| 좌석·설정 | 좌석 77석, 하루 회차 11 |
| 회원 | 140명 (등록 55, 상담 14, 퇴원 71). 다른 시트에만 이름이 있는 64명은 퇴원 상태의 자리표시 회원으로 만들어 이력이 연결되게 함 |
| 모의고사 | 회차 10, 신청 80 |
| 상담일지 | 주간 4칸, 집중관리 일별 45건 |
| 라운딩 | 주차 탭 42, 체크 118,942건, 회차 2,389 (2025-11 ~ 2026-09). 해석할 수 없는 값 39건 건너뜀 |

그대로 넣은 규칙:

- 게시용 셀의 숫자는 그 점수의 벌점(점수가 같은 규칙에 연결), `a`/`A`는 양호, `b`/`B`는 b. `bb`, `ba` 같은 겹친 값은 첫 글자로 읽고 원문을 메모에 남긴다.
- 이름은 좌석번호와 함께 찾고, 같은 이름이 여럿이면 등록 회원을 우선한다. `김지민B` 같은 표기는 그대로 이름이다.
- 근무일지의 근무시간·초과근무는 시트 값을 그대로 쓴다(타임 정의로 다시 계산하지 않음).
- 유일 제약(같은 회원·날짜·항목)에 걸리는 중복 행은 첫 값만 남긴다.

| 마케팅 동의 119건 | 이관 필드 목록에 없었다 | 회원 정식 항목 + 이관 별칭 + 회원 수정 화면 |

### 되메우기 실행

```bash
# 무엇이 바뀔지만 본다

# 실제로 채운다
... --apply
```

근무시간·초과근무·본사확인은 건드리지 않는다. 전체 재적재(`migrate-sheets.ts`)는 지점의 업무 데이터를 지우고 다시 넣으므로 운영에서는 쓰지 않는다.

### 대조 실행

```bash
DATABASE_URL='<운영 DB URL>' pnpm exec tsx scripts/reconcile-sheets.ts --branch DT2 --dir ~/Downloads   --members "고객정보시트_프로젝트12_동탄2.xlsx" --counsel "(동탄) 집중관리일지 -2026.07.xlsx"   --board "게시용 회원생활관리 시트_프로젝트12_동탄2.xlsx" --meals "식사 주문시트_프로젝트12(2026)_동탄2.xlsx"   --worklog "조교근무일지(2026)_ 동탄2.xlsx" --out ./대사결과
```

6개 영역(회원·라운딩·식사·근무·상담·모의고사)을 전부 셀 단위로 맞춘다. 근무는 근무시간·초과근무·**타임 체크 수**까지, 상담은 본문 앞 20자까지, 모의고사는 신청여부·결제일까지 본다. 상세 목록은 실명이 들어가므로 `--out` 폴더의 HTML 로만 나가고 저장소에 넣지 않는다(`대사결과/`는 gitignore).

### 옮긴 데이터를 앱에서 고치는 곳

| 데이터 | 화면 |
|---|---|
| 회원 정보·등록기간·학부모·마케팅 동의 | 회원 › 수정 |

## 8. 전환 절차 제안

1. 본사가 동탄2 지점을 만들고(회차 11, 좌석 77) 벌점 규칙과 현황판 항목(출석, 플래너, 라운딩, 영단어, 점검완료)을 확인한다.
2. 고객정보 시트를 xlsx로 받아 CSV 이관 화면에서 미리보기로 경고를 확인하고 반영한다. 오류 0, 경고 59는 검토만 하면 된다.
3. 식사주문 이번 달, 근무일지 이번 달, 게시용 최근 4주를 스크립트로 옮긴다(스크립트는 고객 확정 후 작성).
4. 상담일지는 최근 한 달을 손으로 옮긴다.
5. 하루 병행 운영 후 시트를 읽기 전용으로 바꾼다.
